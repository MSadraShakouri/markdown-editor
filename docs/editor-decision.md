# تصمیم: موتور ویرایشگر CodeMirror 6

> این سند **تصمیم گرفته‌شده** است، نه پیش‌نهاد. تاریخ تصمیم: ۱۴۰۴/۰۷/۰۴ ·
> شاخه: `arena/01a0da35-markdown-editor` · وضعیت: اجرا شد و در کروم واقعی تست شد.

## ۱. چه چیزی انتخاب شد

**CodeMirror 6**، به‌صورت یک باندل کامیت‌شده در `vendor/codemirror.esm.js`
(بدون مرحلهٔ ساخت در زمان اجرا؛ `tools/build-vendor.mjs` فقط برای بازسازی آن است).

| | `<textarea>` + لایه‌های دست‌ساز | **CodeMirror 6** | CodeMirror 5 |
|---|---|---|---|
| حجم افزوده | ۰ | ۱۸۵KB gzip (۵۴۲ خام) | ۷۳KB gzip (۲۲۰ خام) |
| شکستن خط | باید ساخت | آماده (`lineWrapping`) | آماده |
| شمارهٔ خط کنار خط شکسته | باید اندازه‌گیری شود | خودکار: شماره فقط روی ردیف اول | آماده |
| جهت هر سطر جدا | کل کادر یک جهت | `perLineTextDirection` | **فقط یک جهت برای کل سند** |
| جست‌وجو با هایلایت همهٔ موارد | لایهٔ overlay، با اسکرول از ری می‌افتد | `@codemirror/search` | افزونهٔ آماده |
| مرحلهٔ ساخت | ندارد | یک باندل کامیت‌شده | ندارد |

عددها در همین مخزن با `esbuild --minify` + `gzip` اندازه گرفته شده‌اند.
CM5 فقط به‌خاطر یک محدودیتش کنار گذاشته شد: **یک جهت برای کل سند**، که برای
سند فارسی‌انگلیسی مخلوط پس‌رفت است. `perLineTextDirection` در CM6
همان چیزی است که `<textarea dir="auto">` برای کل کنترل انجام می‌داد، ولی
این‌بار سطر‌به‌سطر.

## ۲. برنامه چطور عوض شد

- `js/editor.mjs` — تنها جایی که CodeMirror را می‌شناسد: تِم، `dir="auto"` روی هر
  سطر، شمارهٔ خط، هایلایت جست‌وجو، قالب‌بندی (H1/H2/پررنگ/ایتالیک/کد)،
  جایگزینی، Enter ادامه‌دهندهٔ فهرست، Tab، حالت فقط‌خواندنی.
- `index.html` — به‌جای `<textarea>` یک `<div id="editor-host">`، و دکمهٔ
  شکستن خط (`#btn-wrap`) که در موبایل به منوی `⋯` می‌رود.
- `js/app.mjs` — همهٔ نقاط اتصال (پیش‌نمایش زنده، شمارش کلمات، نشانگر ذخیره‌نشده،
  جست‌وجو/جایگزینی، اسکرول هم‌گام با نشانگر) از ویرایشگر جدید رد می‌شوند.
- `css/app.css` — پوستهٔ `cm-*` با پیشوند `#editor-host` (تا از استایل‌های تزریقی
  CodeMirror قوی‌تر باشد) و کل لایه‌های قدیمی textarea/backdrop/شماره‌ها حذف شد.

## ۴. چیزهایی که در مسیر پیدا شد و ارزش یادداشت دارند

- **علت باگ پیش‌نمایش:** `[hidden] { display: none !important }` و
  `.editor-pane { display: flex !important }` هم‌وزن‌اند و هر دو `!important`؛
  پس آن‌که دیرتر آمده برنده می‌شود و پنل ویرایشگر پنهان نمی‌شود. این باگ از
  کامیت اولیه (`990795e`) وجود داشت. تست قدیمی فقط `pane.hidden` را می‌خواند و
  همین باعث شد نبیند؛ تست جدید `getComputedStyle` می‌گیرد.
- **`getWrap()` نباید `view.lineWrapping` را بخواند:** آن مقدار یک پاس اندازه‌گیری
  عقب است، پس دکمه و `localStorage` با واقعیت اختلاف پیدا می‌کردند. حالا پرچم
  خودمان برگردانده می‌شود.
- **`setValue()` باید compartmentها را دوباره بدهد** (شکستن خط، فقط‌خواندنی)،
  وگرنه مقدارِ تازه با تنظیمات پیش‌فرض می‌آید.
- **جست‌وجوی CM6 فقط وقتی پنل خودش باز است هایلایت می‌کند**؛ برنامه
  decoration خودش را می‌کشد (`.cm-hl-match` / `.cm-hl-current`) — مزیتش این است
  که هایلایت‌ها بخشی از سندند و با اسکرول جابه‌جا نمی‌شوند (باگ قبلی overlay).

## ۵. تست

- `npm test` → ۶۷ بررسی jsdom (رندر مارک‌داون، سانیتایزر، API گیت‌هاب، دمو).
- `npm run test:browser` → **۳۹ بررسی** روی خود `js/editor.mjs` + **۹۴ بررسی** روی
  برنامهٔ کامل در کروم واقعی (ورود، درخت، ویرایش، جست‌وجو، ذخیره روی API
  شبیه‌سازی‌شده، موبایل ۳۹۰px، جهت سطرها، هندسهٔ شماره‌ها). puppeteer در
  `devDependencies` نیست: بدون آن، سوئیت با پیام روشن skip می‌شود.
- **CodeMirror زیر jsdom اجرا نمی‌شود** (در `measure` خطا می‌دهد) و شکستن خط،
  شماره‌ها و جهت سطرها هندسه‌اند؛ برای همین این دو سوئیت از `npm test` جدا و
  در مرورگر واقعی اجرا می‌شوند.
